# PowerBankMenu GUI review — 2026-09-21

## Scope and design contract

Apple-native macOS menu bar utility, implemented with AppKit. Baseline: `3cd292f` (clean working tree before this task). The UI should make battery/power values easy to scan and account settings easy to enter with either a pointer or keyboard. Retain the existing account, polling, MQTT, credential storage, and immediate general-preference behavior.

- Keep a native status menu, with device names followed by separate battery/output/input rows. Use system fonts and semantic colors; low battery also has a text label.
- Use a template SF Symbol for the menu bar extra, with distinct signed-in/sign-in-required shapes and accessible descriptions. Authentication status is not a claim of device connectivity.
- Group General and Account Settings. Explain that general options apply immediately; label the account action explicitly. The 560 × 460 pt minimum content size and spacing are implementation choices, not Apple requirements.
- Keep secure password entry, visible field labels, and a native grid that expands horizontally. Wrap helper/error text and grow the minimum height when needed.
- Return saves, Escape cancels, Command-comma opens or raises Settings, Command-W closes the active window, and Command-Q quits. Save disables mutable fields and close/cancel controls until completion, so the UI cannot imply an in-progress account save was cancelled.
- Use text plus an icon for errors, restore the email field after a failed request, and expose full connection errors through a native alert.
- Keep the About window at normal window level. No new animation or custom translucent surfaces.
- Preserve macOS 26.0 deployment target, English/Japanese localization, and existing privacy/data scope.

## Verification

Environment: Apple Silicon, macOS 27.0 (26A428), Xcode 27.0 (27A266a), macOS 27 SDK. Minimum deployment remains macOS 26.0. Global `AppleKeyboardUIMode` was 2; no keyboard or appearance preferences were changed. Preview appearance is scoped to the fixture process.

The standalone fixture compiles the actual UI source files with in-memory substitutes for credentials/preferences/services. It has no Keychain, network, log-file setting, or login-item access. It runs as a regular app to expose the same native status menu through a `Device Preview` menu; production remains an accessory app.

## Reproduce the isolated preview

```sh
scripts/build-ui-preview.sh
# The script prints the generated .app path. Launch it normally for Japanese/light
# on a Japanese Mac, or launch its executable with a test-only configuration:
UI_APPEARANCE=dark UI_SCENARIO=error \
  "$TMPDIR/PowerBankMenu-UIPreview.app/Contents/MacOS/PowerBankMenu-UIPreview" \
  -AppleLocale en_US -AppleLanguages '(en)'
```

`UI_SCENARIO=populated` is the default (including low battery and unknown values). Other non-error scenario names leave an unsigned-in empty state. `UI_VERIFY_SUCCESS=1` makes the fake 15-second verification succeed; otherwise it fails with a localized message. Use only dummy input. The fixture is not part of the shipping Xcode target.
